# Prompt universal para especificação de UI/UX

Atue como um especialista sênior em Product Design, UI/UX, Design Systems, arquitetura de informação e engenharia front-end.

Estou anexando um arquivo de referência contendo a ideia, os requisitos e a especificação inicial de um produto digital. Esse produto pode ser uma landing page, site institucional, e-commerce, marketplace, aplicativo mobile, sistema web, dashboard, SaaS, plataforma de conteúdo ou sistema complexo com múltiplos perfis de usuário.

Sua tarefa é analisar profundamente o arquivo anexado e transformá-lo em uma especificação completa, consistente, implementável e visualmente refinada de UI/UX.

O resultado deverá ser um documento de design definitivo, pronto para ser utilizado por uma ferramenta de geração de interfaces, por designers e por desenvolvedores front-end.

## Objetivos principais

- Compreender o propósito do produto e seus objetivos de negócio.
- Identificar os perfis de usuário e suas principais necessidades.
- Mapear os fluxos de navegação e as jornadas mais importantes.
- Organizar a arquitetura de informação.
- Definir uma experiência coerente, intuitiva e acessível.
- Criar um design system reutilizável.
- Especificar todas as telas, componentes, estados e interações relevantes.
- Priorizar clareza, conversão, produtividade e facilidade de uso, conforme a natureza do produto.
- Garantir uma experiência consistente em dispositivos móveis, tablets e desktops.
- Eliminar ambiguidades que possam gerar decisões visuais inconsistentes durante a implementação.

## Regras de interpretação

1. Use o arquivo anexado como fonte principal de requisitos.
2. Preserve os objetivos, funcionalidades e regras de negócio existentes.
3. Não invente funcionalidades que contradigam o produto original.
4. Quando houver lacunas, faça escolhas profissionais e coerentes com o contexto do produto.
5. Se uma decisão depender de uma informação ausente, registre-a na seção “Premissas e decisões de design”.
6. Não faça perguntas ao usuário. Tome decisões fundamentadas.
7. Diferencie claramente:
   - requisitos confirmados;
   - decisões de design;
   - premissas;
   - funcionalidades futuras;
   - elementos que precisam de conteúdo real.
8. Não aplique automaticamente estética de e-commerce, dashboard ou aplicativo se ela não fizer sentido para o produto.
9. Escolha a linguagem visual de acordo com o público, o contexto e os objetivos da aplicação.
10. O documento deve ser específico o suficiente para que outra ferramenta consiga gerar as interfaces sem precisar reinterpretar os requisitos.

## Requisitos para a ferramenta de geração de interface

A implementação visual deverá:

- Seguir fielmente o documento final.
- Usar os tokens definidos no design system.
- Priorizar o fluxo principal.
- Criar as telas necessárias para demonstrar o produto.
- Implementar navegação funcional entre telas.
- Implementar estados interativos principais.
- Utilizar dados de exemplo realistas.
- Evitar lorem ipsum quando o contexto permitir conteúdo específico.
- Manter consistência entre todas as telas.
- Não introduzir cores, componentes ou padrões que contradigam o documento.
- Garantir comportamento responsivo.
- Garantir acessibilidade básica.
- Destacar claramente funcionalidades ainda não conectadas a backend.

## Integrações e configurações externas

- Se o produto utilizar integrações externas (Google Stitch, APIs, MCPs, feature flags), as configurações devem vir de variáveis de ambiente.
- O design gerado não deve expor segredos ou credenciais no código front-end.
- Criar `.env-example` com variáveis de configuração de UI/UX quando necessário.
- Respeitar configurações de tema, endpoints e feature flags vindas do ambiente.
